# ADR-0006: Conventional Commits

## Статус
Принят

## Контекст
Проект требует Consistent commit message format для лучшего генерирования changelog и понимания истории commits. AGENTS.md документирует: "Только [Conventional Commits](https://www.conventionalcommits.org/): <type>(<scope>): <краткое описание>" (Только Conventional Commits: <type>(<scope>): <short description>) и "Типы: feat, fix, chore, docs, test, refactor, ci, build, perf." (Типы: feat, fix, chore, docs, test, refactor, ci, build, perf.)

Реализация использует `mise run check`, который включает linting, а GitHub Actions CI запускает те же проверки.

## Решение
Все коммиты должны следовать формату Conventional Commits: `type(scope): description`. Допустимые типы: feat, fix, chore, docs, test, refactor, ci, build, perf. Scope опционален, но должен относиться к затронутой области (например, booking, meeting, slot, admin). Описание должно быть в импертивном наклонении, английском, без точки в конце.

### Положительные следствия
- **Консистентная история**: Все сообщения о коммитах следуют одному формату, делая git log предсказуемым.
- **Автоматический changelog**: Инструменты могут генерировать changelog из сообщений о коммитах.
- **Лучше tooling**: Многие IDE и инструменты понимают Conventional Commits для навигации и анализа.
- **Четкое значение**: Префикс типа сразу говорит, что kind of change (фича, багфикс, рефакторинг и т.д.).
- **Соответствует требованиям проекта**: Прямой исполнение требования, документированного в AGENTS.md.

### Отрицательные следствия
- **Кривая обучения**: Разработчики, новые для проекта, должны принять формат.
- **Словесные сообщения**: Может казаться wordier по сравнению с free-form commit messages.
- **Угадывание scope**: Иногда определение правильного scope может быть неопределенным.

## Рассмотренные альтернативы
- **Нет формата сообщений о коммитах**: Free-form messages. Проще с начала, но теряет выгоды структурированных коммитов. Сделало бы автоматическое генерирование changelog сложным.
- **Траци-стиль нумерации**: Использование номеров issue вместо Conventional Commits. Будет отслеживать работы items, но не предоставляет той же структуры для анализа коммитов.
- **Кастомный формат**: Проект-специфичный формат. Предоставит структуру, но лишен экосистемного поддержки, который наслаивается Conventional Commits.

## Связано с
- `AGENTS.md` — документирует требование формата коммитов
- `mise run check` — запускает проверки, включая валидацию сообщений о коммитах
- GitHub Actions CI — запускает те же проверки на каждом push
- Типы коммитов: `feat` (функция), `fix` (исправление бага), `chore` (поддержание), `docs` (документация), `test` (добавление/исправление тестов), `refactor` (рефакторинг кода), `ci` (изменения в CI/CD), `build` (система сборки), `perf` (улучшение производительности)
