# ADR-0002: Единственный владелец, без авторизации

## Статус
Принят

## Контекст
Календарь бронирования услуг требует именно одного владельца, который задает типы встреч и доступность. Требования указывают: "Владелец один, авторизации нет. Гость заходит без регистрации" (Есть один владелец, нет авторизации. Гость заходит без регистрации).

## Решение
В системе один жестко заданный владелец без механизмов аутентификации или авторизации. Гости могут бронировать встречи без регистрации или входа в систему. Владелец жестко задан и определен в конфигурации приложения.

### Положительные следствия
- **Простота**: Нет управления пользователями, экранов входа, обработки паролей, контроля доступа на основе ролей (RBAC).
- **Соответствие требованиям**: Прямо реализует явное требование о единственном владельце без авторизации.
- **Низкая сложность UI**: Не нужно реалиовывать потоки авторизации, страницы для гостей могут быть простыми.
- **Быстрая разработка**: Не нужно реализовывать фильтры безопасности, валидацию токенов или пользовательскую базу данных.

### Отрицательные следствия
- **Не многопользовательский**: Календаром может пользоваться только один человек. Нельзя иметь多个 владельцев или администраторов.
- **Не подходит для реального использования**: Любой реальный календарный сервис нуждался бы в нескольких пользователях, ролях и правах доступа.
- **Нет контроля доступа**: Любой гость может записаться на любой доступный слот (в рамках ограничений).

## Рассмотренные альтернативы
- **Полная система авторизации**: Реализация Spring Security с OAuth2 или JWT позволила бы多个 пользователей с разнымиrole, но добавляет значительную сложность (страницы входа, управление токенами, пользовательская база данных, хеширование паролей и т.д.). Перебор для учебного проекта.
- **Базовый доступ на основе ролей**: Добавление простых ролей (владелец, администратор, гость) требовало бы больше изменений в UI и бэкенде, но все равно ограничено по сравнению с полнофункциональным корпоративным безопасностью.

## Связано с
- `CalendarApplication` — главный класс Spring Boot приложения
- `MeetingTypeCatalog` — владелец создает/редактирует типы встреч через админку
- `GuestContext` — управление состоянием гостя без авторизации
- Доменное правило: "Владелец один, авторизации нет. Гость заходит без регистрации."
